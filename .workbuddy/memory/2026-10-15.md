# 2026-10-15

## 小米电视影视聚合方案调研（新增文档）

- 新增 `技术方案/小米电视影视聚合-豆瓣磁力迅雷云盘方案调研.md`（新目录 `技术方案/`）。
- 调研结论要点：
  - 需求拆成 4 环：元数据 / 资源发现 / 资源落地 / 播放。最难是"磁力→迅雷云盘离线→直链"，最好复用是电视端播放。
  - 现成项目盘点：MoviePilot（豆瓣+TMDB 元数据、订阅、搜资源、300+ 插件）、PanSou（网盘资源搜索聚合）、Alist/OpenList（迅雷云盘 Thunder 驱动挂载 + WebDAV）、TVBox 生态（AndroidCatVodSpider Java 源 / drpy2 JS 源，已有豆瓣与磁力熊源）、TorrServe（Android TV 磁力边下边播）、MoonTV/LunaTV/Selene-TV（TV 客户端界面可参考）。
  - 关键约束：豆瓣自 2019 年前后不再开放 API（建议 TMDB 为主源，豆瓣仅作评分/榜单增强，NeoDB 可补充中文元数据）；迅雷云盘离线为非官方逆向接口（参考 sang8052/thunder_pan_agent），接口易变且会员能力本身要钱；磁力+转存+播放属盗版链路，自用与公开分发风险等级不同。
  - 推荐路线：优先"家里放 Docker 服务端（MoviePilot/PanSou/Alist）+ 电视端只装播放器"，零 App 开发；确需自研则按"服务端定统一接口 → 电视端只做 UI 与 ExoPlayer"分层，外部接口全部收敛在服务端。
- 新增目录约定：知识库根下 `技术方案/` 用于存放方案调研与架构设计类文档。

## 需求修订（同日追加）

用户澄清：**自用、主要给父母在小米电视上看、只接受一份网盘会员**（不接受爱奇艺/腾讯/酷喵三份会员）。据此改写了文档，追加"九、需求修订"章节（该节为最终结论，前八章作为技术储备保留）。

- 方向修正：放弃"自研磁力搜索 TV App"，改为"给父母一个海报墙"。核心是把"选资源"留在服务端，电视端零操作。
- 角色分离：维护者（子女，可折腾可自动化）/ 网盘（唯一付费点）/ 使用者（父母，只有"打开→海报→播放"）。
- 网盘选型结论：88VIP 有就用夸克（便宜、TV 版自带海报墙、不风控）；做长期大库选 115（生态最好、STRM+302 工具链成熟、但贵且风控严）；迅雷云盘适合临时离线、不适合做长期 STRM 库；阿里云盘因三方权益包不推荐新选。
- 关键新发现：**网易爆米花**（网盘聚合 + 海报墙，免费无广告，原生直连 8+ 网盘，已上架小米 TV 商店，无需侧载）；夸克网盘 TV 版自带海报墙。
- 四档递进路线：第 0 档装官方 App + 手工转存验证（当天可用）→ 第 1 档 Docker 跑 MoviePilot 做订阅自动化（真正解决追更，价值占 90%）→ 第 2 档 STRM + Emby/Jellyfin 私人影视库 → 第 3 档才考虑自研极简 TV 壳（直连 Emby API，不碰磁力与迅雷接口）。
- STRM 要点：文件内不存直链（会过期），存 pickcode，由插件播放时实时换直链；工具链为 MoviePilot 的 115strm助手 + 115网盘存储 + Emby 302 反代，或 TgtoDrive / SmartStrm / p115strmhelper。
- 必须提前接受的短板：① 独播剧/综艺网盘常无高清源或滞后，不能 100% 替代平台会员，建议保留父母看得最多的那一个平台的会员兜底；② 父母仍需教一次操作。

## 需求再修订（同日第三次追加）

用户再提硬要求：**父母要能自己用遥控器搜索影视资源，且完全不用人工维护**。文档追加"十、需求再修订"章节，部分覆盖第九节结论。

- 方向再次修正：第九节的"海报墙"路线不成立（只能看库里已有的），回到"聚合搜索 App"，但实现方式必须是**"搜索即自动入库"**。
- 核心矛盾：父母搜索内容不可预知 → 必须按需获取 + 延迟要短。只有"按需转存"（几秒）和"实时采集"（无延迟）可用；**磁力离线延迟几十分钟到几小时，从物理上就不适合自助搜索场景**——这是原始方案不成立的根因。
- 关键方案：**小雅（xiaoya-alist）**原理正好命中——聚合约 391 个共享盘、28 万+ 条目，播放时自动调 API 转存到自己网盘再播；配套小雅助手（自动清理转存文件）+ AList Hub（自动更新小雅数据、自动索引、支持搜索、海报）；alist-tvbox 提供 TVBox 对接接口。残留人工维护只有"阿里云盘 token 偶尔要更新"，不是维护内容。
- 风险：阿里云盘对第三方 token 接口政策有收紧趋势，部署前必看项目 README 最新说明。
- 路线终版：A 小雅 + TVBox（主，画质好、维护低）/ B TVBox + 社区采集源（兜底、画质参差）/ C 自建聚合站（要自己维护源）。**推荐 A 为主 + B/C 兜底，同一个 TVBox 里两套并存互为备份。**
- 易被忽略的落地细节：遥控器打字是父母最大门槛，必须确认客户端支持**拼音首字母搜索**和**手机扫码远程输入**；不要指望电视遥控器语音键（第三方 App 能否调用不定）。
- 核心判断更新：关键不是"UI 零操作"，而是**"内容自动供给"**。工程精力应全压在后端自动化稳定性上，而不是电视端 App。
